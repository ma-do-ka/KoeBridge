# 音声コマンド（Build 54）

音声設定の「音声コマンド」で有効にします。マスター設定 `voiceCommandsEnabled` は初期値 OFF。
固定フレーズは編集できません。個別設定 `voiceCommand.<id>` は録音開始時にマスター設定とともにスナップショットされます。

| ID | 発話全体のフレーズ | 効果 | 個別初期値 |
| --- | --- | --- | --- |
| cancelTake | 入力をキャンセルして | この take 自体だけを破棄 | ON |
| newline | 改行して | 改行1つ (`\n`) を入力 | OFF |
| paragraph | 段落を変えて | 改行2つ (`\n\n`) を入力 | OFF |

改行・段落はチャットアプリなどでは送信される場合があります。個別の明示的な有効化が必要です。

## 照合と安全条件

一次認識の確定結果を、整形・後処理・スニペット展開より前に照合します。
NFC 正規化、外側の空白除去、末尾1つの `。` または `.` の許容のみで、発話全体の完全一致が必要です。
内部空白は保持し、部分一致・曖昧一致・LLM による判定はありません。
「ここで改行してと言いました」は通常の文章です。変換 take と Build 51 のテキスト操作は照合を迂回します。

レビュー後、音響レビュー保留、needsReview、incomplete、システム抑止、自動入力 OFF、レビュー後のコマンド不一致を検査します。
**一次結果で一致した候補が条件を満たさなければ blocked-command として破棄し、通常文章として入力・クリップボード救済・履歴保存することはありません。**
レビューや後処理で初めてフレーズになった文章もコマンドには昇格しません。
監査ログには take ID、command ID、条件判定・結果・イベント送信有無だけを記録し、発話本文は含めません。

## 実行順序

command / blocked-command は型付き完了結果として通常文章と同じ順序付きキューを通ります。
キャンセルはその take のみを破棄し、新しい録音をキャンセルしません。
実行ワーカーでも抑止・レビュー状態・自動入力許可を再検査します。
改行は `TextInsertion.deliverCommandText` に固定 command ID を渡し、通常入力と同じ権限、対象・フォーカス、選択範囲、ベースライン、受理確認を使用します。
改行には読み取り可能なベースラインが必須です。確認済み receipt は後続 take の対象補正にも使用します。
通常文章のサニタイズ方針は変更せず、この型付き経路の固定制御文字だけを例外とします。
失敗時はフレーズ入力・制御文字コピー・自動再送を行いません。反映を確認できない場合は入力先の確認を促します。
古い take の通知は新しい録音のオーバーレイを上書きしません。

## 将来の作業

- send: 明示的なクリック／キー確認、確認後の対象再検証、Return キー実行、送信成否の独立した意味付けが必要。
- undo: 対象アプリの操作として明示的確認と対象再検証、Command 修飾キーを含むキー実行が必要。直近の音声入力だけを取り消すとは保証できません。
- delete previous: 同じ未変更フィールドにおける直前の確認済み入力の来歴・正確な範囲と内容の再検証、安全な削除と結果検証が必要。文字数や Backspace 連打による推測は不可。
- フレーズ編集（正規化後の重複拒否を含む）、アプリプロファイル単位のコマンド設定は将来対応。
