# KoeBridge v1.1.4 — 入力診断の重要記録を保持（Build 31）

## この版の目的

連続入力で「認識結果は履歴にあるのに入力先へ反映されない」問題を調べるため、診断の保持・要約処理を修正しました。**入力不具合そのものの解消を宣言する版ではありません。** 自動入力の許可条件、入力順序、再送禁止、無音対策は変更していません。

## 修正内容

- `InputDiagnosticBuffer.swift` の記録保持を一部変更。繰り返すアクセシビリティ応答が増えても、送信計画、修飾キーの状態、送信完了、照合予定値、最初と最後の読取値、終了理由、前後の録音との照合を優先保持します。
- 既存の `input_diag v=1` を維持し、同じログへ `input_summary v=2` を追加。録音IDで、Build・入力先アプリ・認識文字数・送信状況・照合結果をまとめて追えます。利用者が発生時刻を覚えていなくても、残っている記録から対象を探せます。
- 要約内では、本文を挟んだ2回の選択位置読取のうち最初の位置を `first_read_start` / `first_read_length` と表記。送信後に期待する位置 `expected_start` / `expected_length` と混同しないようにしました。旧形式のフィールド名は維持します。
- 診断テストを6件追加。重要イベント保持、Build・アプリ・終了理由の関連付け、位置表記、同意取り消し、保持件数上限、長いフィールドの分割を確認します。

## 記録の場所と条件

**設定 → 履歴と記録 →「問題調査用の記録を残す」** をONにした録音だけが対象です。初期OFFを維持します。OFFへの変更や「動作記録を削除」は処理中の記録にも反映され、取り消した記録を後から保存しません。

保存先は `~/Library/Logs/KoeBridge.log` と、存在する場合は `KoeBridge.log.1` です。本文・音声・APIキー・ウィンドウ名・URL・本文ハッシュは記録しません。追加のアクセシビリティ問い合わせや外部通信もありません。1録音128イベントの保持枠と、1ファイル192KiB・2世代の上限は維持します。要約は同じ保存上限に含まれ、古い録音はローテーションで消えます。

行頭の日時は保存時刻です。要約の `take`、`t_ms`、`uptime_ms` は元のイベントを指します。要約と旧形式の同じイベントを二重に数えないでください。

- 内部ビルド：**31**
- macOS 15以降／Apple Silicon・Intel対応のUniversal開発版
- [アプリZIP](https://github.com/ma-do-ka/KoeBridge/releases/download/v1.1.4/KoeBridge-v1.1.4-macOS-universal-development.zip)

KoeBridgeを終了し、旧アプリを退避してから置き換えてください。**設定 → 情報** で `1.1.4` と `ビルド：31` を確認します。別フォルダーに古いアプリがある場合、旧版を起動し続けないようにしてください。設定・履歴・APIキーを初期化する変更はありません。

配布物は**アドホック署名・Apple公証なしの開発版**です。更新後にmacOSの権限再許可が必要になる場合があります。Developer ID署名済み・公証済みとして配布するものではありません。

## 検証範囲と限界

公開処理は、公開ファイル監査、Pythonテスト、Swiftテスト、自己テスト、Universalビルド、ZIP内の版数・ライセンス・アイコン・署名・両CPU・SHA-256を確認してから配布します。配布先へアップロードしたZIPも再取得して照合します。実行結果はこの版に対応するGitHub Actionsのログが根拠です。

実マイク、Gemini実通信、各入力先アプリでの実入力、利用者環境での症状解消は未確認です。ログは本文を保存しないため、本文のどの文字が異なるかまでは復元できません。送信されたことと、入力先が受理したことを区別し、記録だけで成功を推定しません。
