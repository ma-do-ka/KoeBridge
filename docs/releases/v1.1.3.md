## なぜBuild 29では不十分だったか

Build 29は音量、音が続く長さ、音量の変動を発話の根拠として扱っていました。しかし、環境音にも変動があるため、**音があることと、人が話したことを区別できていませんでした。** さらに、Geminiとの接続準備が終わると、実際に話し始める前から発話開始の通知を送っていました。

「GitHub」は用語候補にも含まれますが、今回の利用環境でどの音声・設定・認識エンジンが引き金だったかは未確定です。特定の語を禁止するのではなく、認識文字列とは独立した発話確認へ置き換えました。

## 変更内容

| 実在する処理・場所 | 区分 | Build 30の動作 |
| --- | --- | --- |
| 録音の音声判定 | 一部置換 | 音量だけの許可を廃止。Mac内のSoundAnalysisでspeech／対応するwhispering分類を確認 |
| 録音中の浮動表示・自動入力 | 一部置換 | 発話確認前、分類失敗、期限切れでは認識候補を表示・自動入力しない |
| 録音冒頭のPCM送信 | 新規追加 | 発話確認前はRAM内に保持し、確認できた最初の発話区間の250ms前から認識へ渡す。発話後の考える間は途中終了させない |
| Geminiへの発話開始通知 | 一部置換 | 接続準備時ではなく、最初の送信対象音声の直前に1回だけ送る |
| 小声・短い発話の復旧 | 維持・補強 | 分類できなくても非ゼロの音声は録音停止後に認識へ渡し、結果が得られれば履歴で確認可能。確認なしに自動入力しない |
| PCM末尾の不完全な区間 | 一部置換 | 最後の短い音を無音として捨てないよう、末尾の音量も判定に含める |
| 問題調査用の記録 | 新規記録項目 | 既存の明示ON時のみ、分類状態・区間数・スコア・許可結果・ビルド番号を記録 |
| 設定画面・用語補助・文脈チェック | 変更なし | 新しいスイッチやログ画面は追加せず、利用者の選択を維持 |
| バージョン／ビルド | 一部置換 | 1.1.3を維持、29 → 30 |

発話分類はMac内で行い、分類のための外部API通信は追加しません。ただし、停止後の復旧を含むGemini認識は引き続きGoogle APIへ音声を送信し、通常の利用料金が発生し得ます。

## 検証

macOSの実際のSoundAnalysis分類器を使い、ゼロ音声、音量が変動する220Hzの音、macOSで生成した「GitHub. Please check the documentation.」という合成音声、同じ音声を振幅0.1倍にした入力を検証します。**音量を下げた合成音声は、人間のささやき声そのものではありません。**

最初の実行では、無音と変調音は許可されず、2種類の合成音声は許可されました。単体テストでは、Build 29の音量条件を通過する変調音が、独立した分類結果なしでは表示・入力を許可されないことも確認しました。初期検証はSwift 225件、自己テスト182ケース・6,899アサーション、Python 7件が成功しています。最終コミットと公開時の実行結果は、対応するGitHub Actionsで確認してください。

公開ワークフローは同じテストを再実行し、Universal ZIPの内容・署名・両CPU対応・SHA-256を検証します。差し替え後のZIPも再ダウンロードし、Info.plistの1.1.3／30と、ビルドしたZIPとのバイト一致を確認します。

## 残る制約

- **ユーザーのマイク・部屋の環境音で、今回の再発が解消したことは未確認です。** Gemini実通信、Appleの実音声認識、入力先アプリを含む一連の実機操作もCIの対象外です。
- 音分類器にも誤検出・見逃しがあります。テレビや他人の声を本人の意図と区別する機能ではありません。
- 初回の候補表示は発話の分類結果を待つため遅れる場合があります。分類器の準備や処理が失敗した場合は自動入力を許可せず、得られた認識結果を履歴で確認する方式です。
- 「GitHub」という語自体は除外していません。実際に話した用語を禁止する修正ではありません。

## 記録と配布の扱い

新しい診断は、**設定 → 履歴と記録 →「問題調査用の記録を残す」** がONで開始した録音のみ対象です。OFF・再ON・動作記録削除をまたぐ古い診断は保存しません。認識本文・音声・APIキー・入力欄の内容は診断に残しません。認識履歴は従来の別機能です。

旧Build 29は `KoeBridge-v1.1.3-build29-rollback.zip` と `SHA256SUMS-build29.txt` として退避します。v1.1.3タグも検証済みBuild 30のソースコミットへ付け替えます。旧コミットは `c05a7e0ac7c8f3e2e74b8d6c956c09984fee087b` です。すでにv1.1.3タグを取得した開発者は、ローカルのタグと配布物のビルド番号が一致しているか確認してください。
