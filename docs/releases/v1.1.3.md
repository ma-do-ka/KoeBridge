# KoeBridge v1.1.3 — 無音・環境音の誤認識による自動入力を抑止（Build 29）

## 背景と原因
無言なのに「GitHub」などが認識・入力される事象への対策です。従来の無音判定は、0.7秒以下の短い操作で認識済み文字がない場合を中心に働いていました。長い無音や、認識モデルがすでに短い単語を返したケースには独立した音声証拠の確認がありません。「GitHub」は登録語の初期候補・開発IT辞書にも含まれますが、**今回の実機事象がどちらの認識エンジンや辞書によるものかは未確定**です。

## 主な変更
- 認識モデルの出した文字列と独立に、16kHz PCMの20ms区間で音量・継続・時間変動を計測します。音声そのものは記録しません。
- 明らかな無音かつ暫定結果がない場合、録音の長さが0.7秒を超えていても「音声入力なし」として自動入力を行いません。
- 声か環境音か判断しきれない音声から認識された文章は、**自動入力せず履歴で確認**できます。小声で話した可能性を考慮し、認識本文を消しません。特定の単語はブラックリスト化しません。
- 信号の裏付けが得られるまで、録音中の浮動パネルに短い暫定認識を表示しません。
- 異常なPCMの浮動小数サンプル値は0に補正し、Int16への変換異常を避けます。異常を検出した音声は自動入力しません。
- **設定 → 履歴と記録 →「問題調査用の記録を残す」**をONにした場合に限り、各録音IDとPCM信号統計・判定結果を端末内の診断ログへ追加します。認識した文章・音声・APIキー・URLは保存しません。追加スイッチや新しいユーザー向けログ画面はありません。

## 検証と限界
Swift Testingとポータブル自己テストに、長い無音、定常環境音、単発クリック、通常の発話、小声、異常サンプル、分割送信の境界を追加しました。公開用ワークフローのビルド・Universal ZIP・署名・SHA-256結果を確認してください。

**この方式は高度な声紋・音素検出（VAD）ではありません。環境音と人間の発話を完全に識別できず、誤認識をゼロにはできません。** 声が小さいと履歴確認になる場合があります。実マイク、Geminiの実通信、Apple Speech、すべての入力先アプリの実機E2Eは未検証です。
