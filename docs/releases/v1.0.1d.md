# KoeBridge v1.0.1d — 更新センターと「一般」画面のUX改善

2026-11-05 / macOS 15以降 / ソースコード版 / Build 23

## 変更内容

- **メニューバーに「アップデートを確認…」を追加**。設定画面の「情報 → アップデート」を開き、GitHubの正式リリースを手動で確認。
- **「情報」画面を更新センターに拡張**。現在のバージョン・ビルド、公式GitHubへのリンク、最新版の状態、最終確認日時を表示。
- **更新の自動確認**。初期ON（いつでもOFF可）。起動時や設定画面を開いたときに必要であれば確認し、成功した確認から24時間は再問い合わせしない。手動確認はいつでも可能。
- **Stableチャンネルのみ対応**。GitHub Releasesの `releases/latest` を利用し、正式リリースのタグ・URL・バージョンを検証。未発表のプレビュー版、非公式URL、無効な応答は受け入れない。通信障害やアクセス制限を「最新版」と誤表示しない。
- **新バージョンへの更新コマンド**。新しい正式リリースがある場合、リリース内容へのリンクと「更新コマンドをコピー」を表示。KoeBridgeを終了してターミナルに貼り付けると、公式Git checkout・無変更状態・タグとバージョン表記を確認してから、ローカルでビルド・署名・置き換え・起動を行う。
- **自動ダウンロード・インストールは未対応**。GitHub Releaseにはソースアーカイブだけがあり、公証済みの署名済みアプリ・安全なアプリアップデート署名を配布していない。未対応のトグルを無効化し、実際には動作しない自動インストール設定を作らない。
- **「一般」を操作中心の画面に再設計**。認識方法、録音ショートカット、自動入力、Gemini文字起こしスタイルを同一画面で直接変更可能に。マイク・入力権限、APIキーの不足、対処方法を表示し、問題解決までの導線を整理。既存のログイン時自動起動・処理時間・ヘルプは維持。
- 公開済みの `v1.0.1c` タグは移動しない。KoeBridgeの内部バージョンは `1.0.1`、リリース表示 `1.0.1d`、Build `23`。

## なぜ自動インストールをONにできないのか

CodexBarはSparkleと署名済み更新アーカイブを利用します。KoeBridgeの現行Releaseに配布可能な署名・公証済みmacOSアプリのアセットはありません。GitHubにあるソースをそのまま実行する完全自動更新は、意図しない変更・途中の失敗・macOS権限の再確認を招くため提供しません。将来、Developer ID署名・公証と更新アーカイブの署名・検証を用意した場合に検討します。

## 更新手順

1. メニューバーの「アップデートを確認…」を選択するか「設定 → 情報 → アップデート」を開く。
2. 新しい正式版が表示されたら「更新コマンドをコピー」を選択。
3. メニューバーからKoeBridgeを終了し、ターミナルでコマンドを実行。
4. 完了後に「設定 → 情報」のバージョン表示とログイン項目の権限を確認。

```bash
cd "$HOME/KoeBridge"
bash scripts/update_from_release.sh v1.0.1d
```

上記は現行v1.0.1dを再確認する例です。実際の更新ではアプリが案内した**新しい正式版のタグ**を使います。GitHubに登録済みの公式リポジトリで、ローカル変更を保護し、危険なforce/resetや無条件のmain追従を行いません。署名に必要なMac側の証明書がない場合は、既存の検証スクリプトが安全に停止します。

## 検証範囲・制約

GitHub Actions（macOS）で公開ファイル監査・Swift Testing・ポータブル自己テスト・Releaseビルド・アプリ生成と署名検証・Updater用Bashの構文テストを行います。GitHubとのライブ通信、オフライン時の画面、手動更新コマンドをユーザーMacで実行するE2E、SwiftUIの各表示倍率での表示は別途実機確認が必要です。
