# KoeBridge v1.1.2 — 入力失敗を切り分ける診断（Build 28）

カーソルが合っているのに入力できない事象を調べるため、既存の **設定 → 履歴と記録 →「問題調査用の記録を残す」** が ON の場合だけ、入力処理の詳細を端末内に記録します。初期値は OFF のままです。

コードから確認できた不具合は修正しました。ただし、個々の Mac で発生する入力失敗の原因はまだ確定していません。再発時の記録から、実際に失敗した段階を特定するためのリリースです。

## ダウンロード

- [KoeBridge v1.1.2 Universal 開発版 ZIP](https://github.com/ma-do-ka/KoeBridge/releases/download/v1.1.2/KoeBridge-v1.1.2-macOS-universal-development.zip)
- [SHA256SUMS.txt](https://github.com/ma-do-ka/KoeBridge/releases/download/v1.1.2/SHA256SUMS.txt)
- macOS 15 以降、Apple Silicon / Intel。バージョン 1.1.2、Build 28。

**アドホック署名の開発版です。Developer ID 署名・Apple 公証はありません。** KoeBridge を終了し、既存アプリを退避してから置き換えてください。更新後に macOS の利用許可を再設定する必要がある場合があります。OS の保護を一括無効化する操作は不要です。

## 確認できた問題と修正

1. **取得不能を「カーソル・入力先が変わった」と扱う問題。** AX の取得失敗、取得値の型不正、実際の不一致を分けました。入力許可の安全条件は維持し、取得できない状態を成功扱いにしません。
2. **短い AX 問い合わせ時間の設定がプロセス全体へ残る経路。** system-wide オブジェクトに設定した時間制限を、問い合わせ終了時に OS の既定値へ戻します。設定・取得・リセットの各 AXError を記録します。[Apple の API 仕様](https://developer.apple.com/documentation/applicationservices/1459345-axuielementsetmessagingtimeout) に沿った修正で、症状への寄与は実環境の記録で確認する必要があります。
3. **選択範囲の比較方法。** 数値範囲は位置と長さで比較します。数値化できない TextMarkerRange は従来の CFEqual を使用します。
4. **大きすぎる旧ログが残る問題。** 現在ファイルだけでなく `.log.1` にも容量上限を適用します。保存先が通常ファイルでない場合は書き込みを拒否します。

## 新しい調査記録

| 調査対象 | 記録する証拠 |
| --- | --- |
| 録音開始時の入力先 | 録音 ID、入力先の PID / bundle ID、取得できた項目、選択位置・長さ |
| 送信前の判定 | 権限、前面アプリ、ウィンドウ・入力欄・選択位置の一致 / 不一致 / 取得不能 |
| macOS との通信 | 実行した AX 操作、AXError 番号、要求した timeout、設定結果、実測所要時間 |
| キー入力の送信 | 予定 / 送信済みチャンク数、修飾キーの状態、部分送信・取消 |
| 送信後の確認 | 読取不能、本文変化なし、本文不一致、選択位置不一致、確認成功、待機時間・残り時間 |
| 連続録音 | 前後の録音 ID の対応、前の入力結果、位置引継ぎを許可 / 拒否した理由 |
| 入力を試みなかった場合 | 自動入力 OFF、再認識の要確認、システム中断、無音、認識失敗 |

新しい入力診断は 1 録音につき最大 128 イベントをメモリに保持し、その入力と後続録音への位置引継ぎの判定が終わってから保存します。先頭の取得情報と末尾の情報、最新の最終結果を優先し、途中で省略した件数を明示します。診断のために AX の本文・タイトルなどを追加取得しません。

## 保存と同意

- **新しい入力 trace は、ON で開始した録音だけを対象にします。** OFF にした場合、処理中の trace を後から保存しません。再度 ON にしても旧録音の trace を復活させません。「動作記録を削除」でも、処理中の旧 trace を失効させます。
- 認識した文章、入力欄の本文、音声、API キー、ウィンドウ名、URL、本文のハッシュは新しい診断に含めません。アプリの bundle ID、数値の選択位置や文字数などは記録します。
- 保存先は従来どおり `~/Library/Logs/KoeBridge.log` と `.log.1`。各 192 KiB、合計最大 384 KiB、ファイル権限 0600。自動アップロードはありません。
- 文字起こし履歴に診断行を混ぜず、ユーザー向けの新しいログ画面も追加しません。認識履歴の保存設定・件数は従来どおりです。

## 実在する画面の変更

| 場所 | 区分 | 内容 |
| --- | --- | --- |
| 設定 → 履歴と記録 → 動作記録 → 問題調査用の記録を残す | 説明文の一部置換 | 下記の説明へ置換。項目名、保存キー、初期 OFF は維持 |
| 同項目のスイッチ | 内部処理の一部置換 | 操作時に同意状態を同期更新し、OFF → ON 間の古い記録を失効 |
| 動作記録を削除 | 内部処理の一部置換 | 保存済みログの削除に先立ち、処理中の旧記録も失効 |
| 通常の入力失敗表示 | 判定理由の一部置換 | 取得不能には既存の安全確認失敗文を使用。取得不能をカーソル移動と断定しない |
| 認識履歴、専門用語の補助、文脈チェック | 変更なし | 保存先、独立チェック、既存の操作を維持 |

置換前：

> 不具合調査に役立つ動作情報を保存します。通常はオフで問題ありません。認識した文章・音声・APIキーは記録しません。

置換後の完成文：

> 入力できなかった段階、入力先アプリの識別子、確認結果や処理時間をこのMacに保存します。通常はオフで問題ありません。認識した文章・入力欄の本文・音声・APIキー・ウィンドウ名・URLは記録しません。

既存の折り返し可能な説明欄を使用し、入力項目や文字数制限は追加していません。設定ページ、README の案内、保存先の説明を揃えています。画面レイアウトの実機確認は未実施です。

## 検証と限界

公開ワークフローで、公開ファイル監査、Python 回帰テスト、Swift Testing、portable self-test、Universal ビルド、ZIP 展開後のメタデータ・ライセンス・アイコン・署名・両アーキテクチャ・SHA-256 を検証してから公開します。

追加した回帰テストは、秘密文字列の除外、記録上限と分割、OFF / 再 ON / 削除による同意失効、ログの順序・権限・ローテーション、読取不能と実際の不一致の区別、同一文字での置換・絵文字・UTF-16 の照合を対象とします。

**実際のマイク、Gemini 実通信、入力先アプリへの入力、AX の実応答は未検証です。** 入力先が本文や選択位置を公開しない場合、受理を確認できないことがあります。確認不能な入力は自動再送せず、従来の復旧履歴を維持します。

再発時の手順と理由コードの読み方は [入力診断の調査ガイド](https://github.com/ma-do-ka/KoeBridge/blob/v1.1.2/docs/input-diagnostics.md) を参照してください。
