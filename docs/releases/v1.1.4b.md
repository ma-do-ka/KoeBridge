# KoeBridge v1.1.4b — Bluetoothマイクの開始処理を改善（Build 32）

## 公開状態

**ソース版の変更記録です。インストール用アプリZIPは未作成・未公開です。**

mainのソース反映と、GitHub Releasesのアプリ配布は別です。既存のv1.1.4 / Build 31のZIPには、この修正は含まれません。このページが存在するだけでv1.1.4bをインストールできるという意味ではありません。配布物が検証・公開されるまでは、READMEの既存ダウンロードリンクを架空のv1.1.4bへ変更しません。

## 変更内容

- マイク開始APIの成功だけで録音中とせず、実際の音声データが安定して届くことを確認します。無音でも正常な音声データが届けば準備完了と判定します。
- Bluetoothの切り替え中などの準備失敗を、1回の開始操作内で最大4回まで再試行します。前のエンジンの終了を待ってから再構築します。各試行2.5秒、全体10秒のアプリ側予算を設けますが、停止したOSドライバー呼び出しを強制終了できるという意味ではありません。
- 準備中のキャンセル後にマイクや認識器が再起動しないようにします。
- 入力形式変更・音声途絶と停止操作が重なった場合も、中断の証拠を保持します。欠けた音声を正常な録音として自動入力しません。
- 変換処理待ちの古い音声を新しい到着と誤認しないようにします。複数の停止要求は同じ終了処理の完了を待ちます。
- 既存の準備表示に進行表示を追加します。任意ONの診断記録に接続方式・入力形式・試行回数・失敗理由を追加します。機器名・音声・認識本文を新たに保存しません。

動画アプリの自動一時停止・再開、動画内の声と本人の声の識別は未実装です。OpenComm2で報告された症状の実機解消を宣言するものではありません。
