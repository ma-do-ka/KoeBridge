# アプリ別プロファイル（Build 50）

音声入力設定の「アプリ別プロファイル」で、アプリごとにエンジン、文体、追加の用語、認識補助、後処理を切り替えられます。

## 設定する

1. 「起動中のアプリ」からアプリを選びます。一覧は通常のウインドウを持つアプリを名前順に表示します。「一覧を更新」で再取得できます。起動していないアプリはバンドルIDを手入力できます。手入力がある場合はそちらを優先します。
2. 「プロファイルを追加」を押すと編集欄が開きます。同じバンドルIDが登録済みなら、その行を開いて選択し、重複を作りません。
3. 表示名、エンジン、文体、追加用語（1行に1語）、各オプションを編集します。「グローバルに従う」は通常の設定を引き継ぎます。変更はその場で保存されます。
4. 有効スイッチで一時停止できます。行の名前で開閉し、ごみ箱ボタンで削除できます。

エンジンはGemini / Apple、文体はそのまま / 読みやすく / エージェントを選べます。用語と文体の認識補助はGeminiで使用します。レビュー用の登録用語、IT用語、文脈チェック、音声再チェック、毎回の音声再チェック、後処理には継承 / オン / オフがあります。「毎回」がオフなら疑わしいときに再チェックする方針です。後処理モードも継承 / オフ / 整える / 丁寧に整えるを選べます。既存の後処理適用条件（エージェント文体や選択テキスト変換を除くなど）は維持されます。

## モデルと優先順位

`AppProfile` はUUID、バンドルID、表示名、有効フラグ、エンジン・文体のraw文字列、追加用語文字列と平坦なoptional overrideを持つCodableモデルです。`UserDefaults` の `appProfiles` にJSON配列として保存し、未保存または壊れたJSONは空配列として読みます。nilは継承、明示的なfalseはオフを意味します。

既存の `TranscriptionOptions` の5番目はBoolではなく `AudioRecheckPolicy` です。プロファイルではbriefのBool?指定に合わせ、`audioRecheckAlways: Bool?` として保存します。trueは `.always`、falseは `.whenSuspicious`、nilはグローバル方針です。他の4つは既存と同名のBool?です。後処理は `postProcessEnabled: Bool?` と `postProcessMode: String?` です。

優先順位は **有効なプロファイルの指定 > グローバル設定 > 既存の実行時エンジンフォールバック** です。エンジン・文体・後処理モードの未知のraw値はグローバルに戻ります。有効かつ完全一致するバンドルIDの最初のプロファイルが適用されます。無効、未知のアプリ、KoeBridge自身、プロファイルなしは通常どおりです。

録音開始時、AXアクセス前に `NSWorkspace` から最前面アプリの識別情報を取得し、設定をtakeに固定します。AX取得に失敗して履歴保存のみとなる録音でも適用されます。選択テキスト変換は、その選択を取得した `InsertionTarget` のアプリ識別情報を再利用します。録音中の設定変更は既に始まったtakeに影響しません。日本語ヒント、自動入力、コンテキスト取得とスニペットは従来のグローバル設定です。

## 用語のマージと接続

追加用語を先頭に、実効設定で有効なグローバル登録用語、明示的に学習した用語、その後に有効なIT用語を並べます。登録用語のスイッチは学習用語にも適用されます。プロファイルの追加用語は、グローバル登録用語がオフでも有効です。`AgentVocabulary` の既存ルールを再利用し、前後空白と空行を除去し、大文字小文字・ダイアクリティカルマークを無視して重複排除、最大100語に制限します。先に現れた表記を採用します。

Geminiの事前接続は、既存の語彙・文体などのスナップショット一致判定をそのまま使います。プロファイルで設定が変わると事前接続を採用できず、通常のコールド接続になることがあります。Liveのsetup形式、マイク、音声の判定ゲートは変更しません。
